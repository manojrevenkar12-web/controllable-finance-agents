# Working on controllable-finance-agents

## Fast feedback

- `pytest -q` (about 10 seconds; needs PostgreSQL at `CFA_TEST_OWNER_URL`, default
  `postgresql://postgres@127.0.0.1:5544/cfa_test`; builds `data/` on first run).
- `ruff check cfa tests && ruff format --check cfa tests && mypy cfa`.
- `cfa eval dev --no-llm` (about 15 seconds) for real numbers; `cfa release <variant>` applies the gates on test.
- Model calls go through the Claude Code CLI and are cached in `fixtures/llm_cache/` (committed). `CFA_LLM=off`
  turns a cache miss into an error; CI runs that way and reproduces the committed reports exactly.

## Invariants (each has a test)

1. **Agents propose; people decide.** Agents create proposals through the ledger API. Bookings, payment holds and
   journal entries are written only when an accountant approves, never by the proposer: the database refuses a
   decision by the creator and any change to a decided proposal (`tests/test_ledger.py`).
2. **Access is decided by the ledger, not by the agent.** Every request runs in a transaction bound to the
   caller's company; row-level security holds even without the service; the runtime role cannot delete or alter
   anything. The MCP server acts with the person's token and passes refusals on (`tests/test_pipeline.py`).
3. **Agents never see the truth.** `cfa/agents` and `cfa/mcp_server.py` do not import `cfa.sim` or `cfa.evals`
   and never name truth files; prompts do not describe the simulation (`tests/test_isolation.py`).
4. **Append-only records.** Journal entries and the audit log refuse updates and deletes.
5. **Settings live in `config/`.** `config/thresholds.yaml` is generated by `cfa calibrate` on dev only.
6. **Test is for gates.** Thresholds and agent changes are made on dev. When test or the held-out month has been
   studied, say so in `docs/EVALUATION.md`.
7. **Change behaviour, bump the version** in `config/agents.yaml`.

## Held-out rule

`heldout/<set>/` holds cases written by someone who has not read the code. Never change an agent to pass a set
before its first run is recorded in `reports/heldout/<set>/first_run.json`, which is never rewritten. If you
study a set's failures, write `regression` to `heldout/<set>/STATUS` and have someone who has not seen the code
write a new set from `heldout/WRITING_CASES.md` only.
